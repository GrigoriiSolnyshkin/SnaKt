    Make the Char code range a type invariant
    
    A Char is embedded as an unbounded Viper Int, so nothing constrained it to
    the range Kotlin Char values occupy. CharTypeEmbedding now carries that range
    as a pure invariant, which puts it on parameter preconditions, return
    postconditions, loop invariants and forall antecedents at once instead of in
    one linearization branch.
    
    Loop heads and forall antecedents collect pure invariants generally rather than
    Char's in particular, so a Nothing-typed variable in scope now contributes
    false, matching what ContractBuilder already does for a Nothing parameter.
    
    Char-producing operations have to guarantee the range for the invariant to be
    derivable rather than merely assertable. addCharInt and subCharInt now reduce
    their result with a new truncateToChar domain function, which is what Kotlin's
    truncation to the low 16 bits comes to; stringGet reduces its result too,
    since a string is a sequence of unconstrained Ints.
    
    Truncating means '0' + length wraps for a long enough string, which z_function's
    encoding of z-values as digits offset from '0' relies on not happening, so that
    test now states the bound on the length it always needed.

    Make the Char code range a type invariant
    
    A Char is embedded as an unbounded Viper Int, so nothing constrained it to
    the range Kotlin Char values occupy. CharTypeEmbedding now carries that range
    as a pure invariant, which puts it on parameter preconditions, return
    postconditions, loop invariants and forall antecedents at once instead of in
    one linearization branch.
    
    Loop heads and forall antecedents collect pure invariants generally rather than
    Char's in particular, so a Nothing-typed variable in scope now contributes
    false, matching what ContractBuilder already does for a Nothing parameter.
    
    Char-producing operations have to guarantee the range for the invariant to be
    derivable rather than merely assertable. addCharInt and subCharInt now reduce
    their result with a new truncateToChar domain function, which is what Kotlin's
    truncation to the low 16 bits comes to; stringGet reduces its result too,
    since a string is a sequence of unconstrained Ints.
    
    Truncating means '0' + length wraps for a long enough string, which z_function's
    encoding of z-values as digits offset from '0' relies on not happening, so that
    test now states the bound on the length it always needed.

Author: Komiputer <jesyspa+autodev@gmail.com>
Date:   2026-08-26 03:35:26 +0200

    Make the Char code range a type invariant
    
    A Char is embedded as an unbounded Viper Int, so nothing constrained it to
    the range Kotlin Char values occupy. CharTypeEmbedding now carries that range
    as a pure invariant, which puts it on parameter preconditions, return
    postconditions, loop invariants and forall antecedents at once instead of in
    one linearization branch.
    
    Loop heads and forall antecedents collect pure invariants generally rather than
    Char's in particular, so a Nothing-typed variable in scope now contributes
    false, matching what ContractBuilder already does for a Nothing parameter.
    
    Char-producing operations have to guarantee the range for the invariant to be
    derivable rather than merely assertable. addCharInt and subCharInt now reduce
    their result with a new truncateToChar domain function, which is what Kotlin's
    truncation to the low 16 bits comes to; stringGet reduces its result too,
    since a string is a sequence of unconstrained Ints.
    
    Truncating means '0' + length wraps for a long enough string, which z_function's
    encoding of z-values as digits offset from '0' relies on not happening, so that
    test now states the bound on the length it always needed.
